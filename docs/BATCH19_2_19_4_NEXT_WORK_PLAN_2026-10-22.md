## 19-2｜GM 角色與動作測試中心

**目的：** 手機與桌機皆以「選測試對象 → 選紀元／怪物 → 看動畫 → 點動作」為主，不要長篇開發說明、歷史批次入口與大量 JSON 擠佔畫面。以既有 `3d-test/gm-era-sprites.mjs`、`3d-test/index.html`、`3d-test/test-center.css`、`3d-test/test-center.js` 為初查入口；執行前以最新 main 確認。

**保留：**
- 三紀元正式玩家、正式怪物原型與中文身份選擇；地圖／懸賞／競技／災厄／特殊副本／鏡像／虛空／高維十王／異宇宙等原有可測試能力，異宇宙細選項僅在相關模式顯示。
- 玩家／怪物六動作（待機、攻擊、受擊、閃避、回位、死亡）；共用一組操作區，依「玩家／怪物／對戰」模式控制目標。
- 玩家攻擊怪物、怪物攻擊玩家的對戰測試、播放速度、重播、動畫預覽、必要時簡潔雙方血條、最大化／返回。
- GM 授權隔離、Sprite/Actor/Pool/Renderer/快取／故障注入／既有自動化驗收能力與正式遊戲資料安全邊界。

**從一般介面移除或合併：**
- 第17批「30隻並排比較」歷史批次入口；若比較能力仍有工程價值，改為進階通用功能，不再常駐或以批次命名。
- 重複的玩家／怪物六動作按鈕、冗長的正式攻擊技術介紹、原型代碼與身份數量說明、選單已顯示的身份重述、配色英文／尺寸％／特效／動作技術名稱、實測倍率與 px 高度等。
- 正常成功時的「512×512、SHA-256已驗證、載入成功」提示、舊「目標」方框及無用途重複提示（移除前確認不影響正式動畫或測試）。
- 一般頁面不直接顯示原始 JSON、資源統計、快取技術資料、SHA 等。保留必要診斷資料於內部；缺圖回退／重載／快取診斷移入預設收合的「進階診斷」，正常時不佔高度；異常時顯示簡短錯誤與重試。
- 盤點 `test-center.css` 過時規則與 `C-08-CHARACTER`／`C-15-BATTLE` 歷史自動化入口，僅移除確認無依賴的 UI／CSS，不破壞測試 API。

**驗收：** 真實手機直／橫向及桌機，選單可操作、資訊不重複、六動作與雙向對戰完整、異宇宙與特殊副本可選、最大化／返回正常、資源失敗可恢復、GM 授權隔離、既有 Browser／Runtime／Actions 通過。不得因刪 UI 而刪核心測試能力。

## 19-3｜全正式戰鬥畫面智慧定位

**使用者實際問題：** 點進部分戰鬥後仍須手動上下滑，才能看見動畫與玩家／怪物框。目標是進場即盡可能看見動畫、雙方名稱／血條／資訊框與停止按鈕；空間不足時優先動畫與必要戰鬥資訊，不可縮小第19-1批已封箱的角色視覺大小。

**已知靜態程式因素（待真實瀏覽器驗證）：**
- `combat-viewport-coordinator.js` 現在僅以 `.formal-b-shared-stage` 的 bounding rect 中心對齊 visualViewport；`focused=true` 後通常不再重新定位，場次未換 route 時可能不重新定位。
- `3d-test/formal-player-sprites.css` 在手機把敵方框、舞台、玩家框分開排序，且第19-1批增高舞台；短螢幕難以全部同時容納。
- `battle-mobile-viewport.css` 以 `#main::after` 預留 `50dvh` 捲動空間；需實測是否造成過大空白與 scroll 邊界問題。
- 正式 Renderer 資源非同步載入、Ready／pending、不同戰鬥模式／連戰換場會改變元素尺寸與時序。

**施工步驟（同一批整合，不必拆 PR）：**
1. **19-3A 實測盤點：** Playwright 原生正式入口，桌機1365×900、手機直向390×844、橫向844×390，量測動畫、玩家框、怪物框、停止鈕、可視 viewport、安全區與實際需捲動量；逐模式確認地圖／懸賞／競技／文明災厄／特殊怪／高維十王／異宇宙／虛空／鏡像等。
2. **19-3B 智慧定位：** 改用動畫＋雙方關鍵資訊＋停止鈕的可視性與總範圍做定位，能全顯示則全顯示；空間不足採明確優先順序與可測量的安全退讓。不可每次 DOM 變動就反覆搶捲動；尊重使用者 touch/wheel/keyboard 手動操作。
3. **19-3C 微調版面：** 優先 CSS 減少無用空白、間距，調整資訊框顯示策略及 `50dvh` 預留；維持玩家左、怪物右、停止鈕上方、透明背景及正式戰鬥原有資訊與功能。不可用縮小動畫或改戰鬥數值解決。
4. **19-3D 回歸：** 載入前／後無明顯跳動、連戰換場不亂捲、轉向、返回重進、手動滑動後不被拉回、背景戰鬥／極簡模式不誤觸，三視窗多模式 Browser／Runtime／Actions 與同SHA Pages 驗收。

**設計限制：** 若短螢幕無法物理上同時容納全部資訊，必須記錄實際限制與優先可視區域，不得假稱全部同屏。不得回退第19-1批可見高度與 Boss 比例驗收。
