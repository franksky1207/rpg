# 《文明戰線》怪物製圖初版規則 v1.0

> 狀態：討論初版／供後續怪物製圖及戰鬥動畫批次引用，**非施工指令或驗收完成聲明**  
> 日期：2026-10-19  
> 範圍：三紀元地圖與特殊戰鬥、異宇宙、虛空、鏡像戰的怪物視覺素材  
> 依據：既有第 12 批主角正式動畫、現有戰鬥視覺架構、智慧下載與 Service Worker 快取政策。

## 1. 核心原則

1. **優先「正式戰鬥可用」而非精美**：小尺寸辨識、站位自然、動畫流暢、風格一致，優先於精細裝飾。
2. **依怪物名稱的完整語意決定外觀**，不是一隻怪配一張圖，也不按每張地圖逐一製圖。不同名字、等級、數值、普通／菁英／Boss 可共用相同造型。
3. **每種造型以單張完整透明 Sprite 為主**；不強制逐格動畫、骨骼、分層或獨立武器。
4. **全部怪物共用六種正式戰鬥動畫狀態**，不針對各怪物製作專屬動作。
5. **不更動正式戰鬥的計算、回合、結算、存檔、離線／背景戰鬥或主角第 12 批動畫**。
6. 本文件採低美術門檻，避免因過度嚴格標準造成不斷重畫或工期失控。

## 2. 圖片交付規格（初版建議）

| 項目 | 規則 |
| --- | --- |
| 正式檔案 | 透明 WebP；一張圖一種視覺原型 |
| 基準畫布 | 優先 512×512；戰艦等特殊比例允許等效長寬比／額外留白，不得拉伸變形 |
| 體態與主體 | 完整單體；人形全身、艦艇全艦、巨構完整主要輪廓 |
| 正式朝向 | **怪物站右側，預設面向左；優先左前 3/4**，也允許適合的純左側視角 |
| 風格 | 2D Sprite、風格化科幻、正常比例、中等細節；非 Q 版、非宣傳海報式背景圖 |
| 禁止混入 | 背景／地板／文字／UI／第二隻怪／邊框／棋盤格假透明 |
| 光效 | 僅少量局部發光，避免大面積光圈、半月光波、密集碎片 |
| 容量 | 100～250 KB 僅作初步參考值；須以可讀性、透明品質、手機表現決定，不作硬性淘汰閾值 |
| 武器 | 可與怪物主體畫在一起，不要求獨立圖層 |
| 細節 | 避免大量細碎突起與紋理；縮小後仍可辨識類型 |

**朝向例外：** GM 動畫測試中心可左右對調與水平翻轉；測試操作不改變正式素材的左向基準。艦艇、球體、能量體等不適合擬人化頭部朝向的造型，以明確朝玩家側的攻擊方向／構圖為準。

## 3. 語意分類與共用策略

- 初步以 **24 種共用視覺原型**當作規劃基準，必要時預留最多約 **6 種重要首領專用造型**。數字屬於**討論預算**，不是必須恰好產出 24 或 30 張。
- 合併方向包括：人形士兵／重甲統帥／神性人形、無人機／機甲／大型機械／炮台／核心、戰機／戰艦／母艦／堡壘／巨構、獸類／蟲巢／生化／聚合異形、能量／虛影／奇點／維度／法則／文明化身。
- 優先依「形體核心名詞」分類，例如「母艦」「母巢」「巨像」「主機」「戰艦」，再輔以派系、顏色、等級語意。**不可因名稱含「王」就一律指派人形王者造型。**
- 「黑潮母艦」與「黑潮母巢」不得因相同前綴被硬合併；「星際海盜」與「海盜破城艦」應按人形／艦艇形體區分。
- 建立 **正式敵人身份（含模式／紀元／穩定 ID）→ 造型 ID** 的固定映射表；文字名稱不明確時標示待人工覆核。正式執行**不可每次戰鬥重新猜測或隨機指定**造型。
- 重要 Boss（尤其高維十王、文明災厄、各章關鍵首領）可優先維持可辨識性，**但不規定 Boss 必須獨立製圖**。
- 銀河地圖、懸賞、競技、災厄；宇宙主線百王與各副本；高維十王與其競技投影；異宇宙 200 宇宙×5 階；虛空與隨機特殊怪物均納入映射。高維競技投影優先重用十王造型；鏡像戰優先使用正式玩家外觀，不新造一般怪物圖。
- 怪物能力、名稱、獎勵與資料身份不因視覺共用而改動。

## 4. 體型、縮放與定位

為保留統一動畫系統，只定義**三種輕量顯示輪廓設定**：

1. **直立型**：士兵、機甲、人形首領；前衝／後仰／傾倒。
2. **橫向型**：戰艦、母艦、部分巨獸；平移／輕旋轉／淡出。
3. **漂浮型**：能量核心、虛影、奇點；微浮動／震動／下沉淡出。

三種類型**僅是動畫參數差異，非三套動畫引擎**。

- 畫面大小由容器及角色可視空間決定，而非真實世界尺寸；S／M／L／XL 僅是候選視覺等級。
- 參考高度：小型約主角 60～75%、人形 90～110%、大型 115～130%、巨構／Boss 130～150%；皆為初始值，正式需以手機畫面安全範圍調整，不能裁掉怪物、主角或 HP。
- 每張圖有可重用的視覺重心、定位錨點及攻擊接觸參數；優先自動推導，特殊造型才人工修正。
- 不要求漂浮／艦艇敵人有腳底接地點，不因素材比例而強行扭曲圖片。
- 桌機與手機均維持**玩家左、怪物右**；無戰鬥文字訊息框。

## 5. 六種共用怪物動畫

| 狀態 | 極簡呈現 |
| --- | --- |
| 待機 | 靜止或極小幅度微浮動 |
| 攻擊 | 整張 Sprite 向**左**短距離前衝，再回到基準位置 |
| 受擊 | 向**右**輕退／短暫震動 |
| 閃避 | 向**右**短距離位移 |
| 回位 | 平滑回到原位 |
| 死亡 | 直立型傾斜／下沉淡出；橫向、漂浮型可輕旋轉／下沉淡出 |

- 玩家第 12 批既有**短距離上挑斬**不變。怪物不必複製主角上挑斬，不製作武器逐格、刀光、半月光波或大型攻擊特效。
- 全部以既有正式戰鬥事件與動畫時鐘驅動；不另起動畫循環、計時 Owner 或新 Canvas／RAF。
- 動畫不得延遲或更動命中、閃避、死亡判定及戰鬥結算。連續戰鬥中新場到來時，舊動畫需可中斷、清理並安全切換。

## 6. 智慧下載、快取與手機效能

沿用既有 `resource-cache-client.js`、`resource-cache-sw.js`、`resource-manifest.json`、`backgroundpreload.js`，**不重新設計下載系統**。

**目前現況：** Service Worker 已支援快取版控與背景預載；背景自動下載清單目前只含指定正式背景、配樂與音效（現有程式策略為 49 個選定媒體），**尚未自動背景預載未來怪物圖片**。

**怪物圖納入後的目標行為：**
1. 首次遊戲載入完成後，溫和背景下載正式怪物圖片至持久化 Cache Storage。
2. 之後以內容 SHA／清單版號核對，版本相同時直接使用本機快取，只重取變更檔案。
3. **下載快取 ≠ RAM／GPU 解碼常駐**：即使全數圖片已下載到本機，戰鬥期間只解碼當前及有限必要的鄰近素材；尊重現有 Sprite Pool、生命週期及退場釋放。
4. 不因 1,000 階異宇宙而建 1,000 張或一次解碼全部圖；快取不足、瀏覽器清理或首次網路失敗時依安全回退處理。
5. 下載與解碼不能阻塞遊戲啟動或拖慢戰鬥；不得因圖片失效造成 HP、結算、背景戰鬥、離線獎勵、極簡模式異常。
6. 設定中的「已下載資源狀態」與「清除已下載資源」沿用現有機制；清除資源不可清除角色進度與帳號資料。
7. 以 iPhone 異宇宙長時間連戰作效能重點；避免大批圖片同時解碼、頻繁建立物件或未清理的場景資源。

## 7. 可用驗收：A／B／C 三級

- **A／直接採用**：完整透明單體、朝向正確、輪廓清楚、手機實際顯示仍能辨識、站位及六動作正常、風格一致。
- **B／小修後採用**：輕微邊緣、尺寸、偏位、亮度等問題；僅須局部簡修即可用。
- **C／退件**：主體缺損、錯誤朝向又不可合理翻轉、假透明、難以辨認、風格嚴重衝突、無法自然套用共用動畫或手機運行不穩。

**驗收不能只看大圖。** 每個候選至少需在正式桌機、iPhone 直向與必要橫向畫面以實際渲染尺寸檢查：輪廓、站位、HP 可見、前衝、受擊、閃避、回位、死亡、連續切換和缺圖回退。GM 與正式戰鬥應使用同一正式素材、定位及動畫邏輯。不要因不影響小尺寸閱讀的美術細節反覆重畫。

## 8. 後續製作程序（尚未開工）

1. 核對所有正式敵人 ID／名稱來源，完成語意分類與待覆核清單。
2. 確認最少可用原型與重要 Boss 例外；**不預先強制圖片總數**。
3. 每種造型生成單張圖，檢查透明度、構圖、朝向、尺寸與檔案大小。
4. 以既有正式戰鬥事件測試三種體型設定、共用六動作與手機可用性。
5. 通過 A／B 驗收後才建立固定映射、納入智慧下載清單與正式發布資產。
6. 每一批遵循一次整合施工、自我檢查、最新提交 SHA 的 GitHub Actions／Pages／Runtime 實際驗收、封箱紀錄；未驗收不得宣稱完成。

## 9. 不變更邊界

- 不變更角色第 12 批攻擊／三紀元主角圖與正式造型。
- 不變更敵人資料、玩家數值、戰鬥回合、傷害計算、勝敗、戰利品、存檔 schema、帳號權限、GM 數值權限。
- 不改背景戰鬥、極簡靜音、離線收益、Fast Catch-up、倍速等機制。
- 不恢復已移除的戰鬥文字及訊息框。
- GM 動畫測試中心保持單一簡潔介面；可切左右站位／翻轉，但不另外建立平行動畫核心。
- 本文件為**初版討論規格**；24 種原型、6 種首領預留額度、容量及尺寸均是可依實測調整的初始建議。
