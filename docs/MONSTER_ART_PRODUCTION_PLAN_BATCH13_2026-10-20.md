## 3. 外型分類與數量（暫定，不是定稿）
- 使用語意分類，不能只用文字關鍵字：例如「堡壘戍衛兵」是士兵、「生化突擊兵」是生化人形，「母艦」絕不能映射成士兵。
- 12 種概念大類：輕裝人形；重裝人形；軍官／王者；無人機；機甲／機械巨兵；戰車／炮台；戰艦／母艦；堡壘／巨構；異獸／巨獸；生化／母巢；機械核心／主腦；能量／特殊存在。分類名稱可調整，**assetId 不任意重編**。
- 暫訂基礎圖 36 張：輕裝人形 3、重裝人形 3、軍官王者 4、無人機 3、機甲巨兵 3、戰車炮台 2、戰艦母艦 4、堡壘巨構 3、異獸巨獸 3、生化母巢 2、核心主腦 3、能量特殊 3；另保留 **銀河最終 Boss Lv500、宇宙最終 Boss U100 各 1 張獨立圖**，合計 **38 張目標方案**。
- 38 是**暫訂資源預算**，不是硬性上限；先完成 609 筆映射、9 種特殊怪能否共用、重要 Boss 例外盤點，再批准最終數量。不能為了維持 38 張把戰艦、巢穴、巨獸硬塞進不合理外觀；也不因為名稱不同就新增一張。
- 普通／菁英適度共用：大小、配色、亮度、裝飾／局部效果分層區分；重要 Boss 必須有足夠辨識度；可適當新增 `unique` 圖。
- 推薦六種製圖前驗證代表型：人形士兵、重型機甲、戰艦、宇宙巨獸、機械核心、大型母巢；**先審美術、朝向、邊界、定位、攻擊模板，再批次製圖**；驗證圖通過後可納入 38 張。

## 4. 建議素材目錄、ID 與資料契約
**下面為擬新增結構，尚未存在／未施工**。
```text
assets/monsters/v1/
  humanoid/       # 輕重裝、指揮官、王者
  mechanical/     # 無人機、機甲、戰車、炮台
  starship/       # 戰艦、母艦
  structure/      # 堡壘、巨構
  creature/       # 異獸
  biological/     # 生化、母巢
  core/           # 核心、主腦
  energy/         # 能量／抽象存在
  unique/         # 獨立 Boss／特殊怪
data/monsters/
  monster-assets.json
  monster-mappings.json
  monster-variants.json
```
- 所有檔案使用固定英文 ID／小寫路徑，例如 `hm-01`、`ship-03`，避免以中文名稱、等級、文件所在階段構成檔案名稱；不能覆蓋玩家 `assets/era-player/v1/`。
- `monster-assets.json`：每張圖的 assetId、相對路徑、512×512 尺寸、WebP 格式、檔案 bytes、SHA-256、alphaBounds、授權／來源、素材版本、正式允許使用狀態；不記不存在圖片的假 SHA。
- `monster-mappings.json`：**609 個完整且不重複正式身份鍵**，來源 world/region/map/slot 或 `universe-boss-001` 等穩定 ID、顯示名稱、kind、assetId、variantId、animationType、重要 Boss 例外；宇宙特殊名稱覆蓋透過原 ID 查詢。正式產生映射前要確認原遊戲每張地圖、每個 slot 的穩定來源鍵，避免只用 level/name 錯配。
- `monster-variants.json`：variantId、palette／色彩調整、scale、pivot、visualBounds、offsetX/Y、maxDisplaySize、facing `left-3/4`、動作模板；數值需界線驗證。暫定模型例示，不是既有執行格式：
```json
{"id":"galaxy-map-001","name":"武裝暴徒","assetId":"hm-01","variantId":"original","scale":1,"facing":"left-3/4","offsetX":0,"offsetY":0}
```
- **畫面定位**：怪物在右、面左，角色動畫中心與怪物錨點對準，依可視邊界計算而非整張透明圖的幾何中心；戰艦橫長、人形直立、母巢不規則者單獨驗證。不因圖片延遲載入導致戰鬥版面跳動。
- **改色原則**：輕度色相、飽和度、亮度變化可共享基礎圖；不可讓眼睛、武器、發光部件失真；差異明顯的 Boss 應獨立製圖，不能只靠整圖 CSS 濾鏡冒充獨特造型。

## 5. 美術、格式與動畫固定原則
- 2.5D B；3/4 視角；怪物原生**面向左**、玩家面右；透明背景；角色小尺寸下仍輪廓清楚；不求 3D 大作細節；風格、光源、線條、陰影、主體占比一致。
- 輸出正式素材 512×512 **透明 WebP**，不變形拉伸，保留適度透明邊界，記錄 alphaBounds、可視中心和 pivot；圖片是否需要獨立攻擊分層須依六型試作品驗證，**不要求每怪六張動作圖**。高解析原圖留在交接 ZIP 的 `sources/`，不放遊戲 Runtime 載入清單。
- `animationType` 應在製圖前確定：人形短突刺／小幅前移、機甲機械攻擊、戰艦砲擊、異獸撲擊、核心脈衝、巨構固定主體發射效果；受擊與死亡盡量重用既有正式效果；沒有半月光環、不新增大揮刀。
- 正式戰鬥與 GM 須使用同一資料登錄及渲染計算，不准 GM 另做看似成功的假預覽。

## 6. 智慧下載、快取、效能與失效退回
- 接入既有智慧下載／本地清除及版本更新策略；玩家進遊戲可背景下載可重用的怪物素材，但**下載到磁碟不代表全部解碼並常駐 GPU／RAM**。
- 戰鬥預熱當前／即將遇到的怪物；同圖共用解碼快取與實例生命週期，退出／中斷／頁面隱藏要釋放不再使用資源；控制並行數、解碼、記憶體與 iPhone 發熱，不能直接挪用玩家專屬 SpritePool 的驗證白名單。
- 下載檔以 SHA-256、版本和 bytes 檢查，資源更新可辨識；載入失敗須有一致的重試與 fallback，**不得讓正式戰鬥消失／切模式失效／文明災厄進入失敗**；背景、極簡、背景戰鬥與 Fast Catch-up 行為不可回歸。
- 先核對現有資源總表、快取清除、智慧下載預載管線，再決定修改點；不憑規劃假定目前已支援怪物 Sprite。

## 7. GM「角色與動作測試中心」整合
- **沿用現有測試中心**，只加必要「怪物測試」分頁／分類，不能建立第二個怪物測試中心或大改 UI。
- 能依銀河／宇宙／特殊怪、地圖、Boss、圖片 ID 選怪，顯示**609 身份對應表**與同圖共用清單；可切換圖片 variant／顏色／倍率／pivot 並顯示 assetId、來源、尺寸、快取狀態。
- 測試待機、攻擊、受擊、死亡，及玩家左／怪物右對打；大小和置中、連續換怪、模式來回、資源遺失／重載都要覆蓋；測試中心與正式使用相同渲染與動畫模板。

## 8. ChatGPT 製圖、ZIP 打包與 Codex 交接
1. **先產出 609 筆完整身份／圖像映射表，逐筆語意審核**；輸出 38 張候選 ID／概念／重用清單與例外；未審核前不開始大量製圖。
2. 用六張差異極大的代表圖完成美術小型驗證；通過才按類別**小組製圖**，每張固定 ID、分類、視角、透明邊界。製圖結果需實際取得來源檔，不能只憑對話內的預覽宣稱已保存。
3. 逐張以真實檔案轉 512×512 WebP、驗證格式／alpha／裁切／尺寸／SHA、比對外觀及方向，保存原圖。
4. 最後整理**一份完整 ZIP** 交付 Codex 一次整合，不要求使用者手動逐圖上傳 GitHub。預計內容：
```text
civilization-monsters-map-v1.zip
  assets/monsters/v1/{humanoid,mechanical,starship,structure,creature,biological,core,energy,unique}/...webp
  data/monsters/{monster-assets.json,monster-mappings.json,monster-variants.json}
  sources/                 # 高解析原始素材，僅交接備份，不寫入正式網站部署清單
  manifest.sha256
  VALIDATION_REPORT.json
  README-CODEX.md
```
5. ZIP 完成後**重新解壓**／驗證每個檔案的 SHA、PNG/WebP 真實格式、512×512、透明度、路徑安全、重複 ID、缺圖、全部 609 筆對應、動作和顏色合法性；只有全部通過才能宣告 ZIP 完成。**如任一圖沒有可處理的實體檔，須補圖，不可虛構 ZIP 內容**。
6. `README-CODEX.md` 清楚指定目錄、機制、匯入／擴充、禁止改動數值／存檔／舊 UI、測試清單和验收閘門。Codex 在最新 main 上整合並回報 PR、commit SHA、Actions、Pages／Runtime、正式／GM 結果。使用者 iPhone／桌機實測列為發布後確認，不冒稱 CI 等於真機驗收。
- ZIP 應是**可重現可校驗的輸出**，圖片生成／壓縮／檔案驗證與 Codex 的 GitHub 施工為不同責任層。交接時注意 Codex 執行環境如何取得 ZIP：不得假設可直接讀取 ChatGPT 沙盒路徑；實際需提供使用者可轉交的檔案／附檔。
