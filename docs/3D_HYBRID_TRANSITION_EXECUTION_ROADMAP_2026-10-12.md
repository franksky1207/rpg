## 1. 每批共通的不可破壞邊界
1. 所有正式遊戲運算 owner 不改：戰鬥數值／亂數／收益／掉落／結算、合法副本、關卡解鎖、三紀元／異宇宙 200×5、回顧、轉生、存檔／雲端、離線收益與 GM 授權。
2. GM 背景戰鬥、1×／1.5×／GM 2×、Fast Catch-up、連戰不中斷；視覺事件不延遲戰鬥計算，過時事件及音效不補播。
3. 音樂及音效繼續由正式唯一 owner 管理；視覺層只接事件，不另建互相衝突的播放器。
4. 保留 Babylon.js 本地引擎、骨架 53 骨／9 掛點／三 LOD、五槽自由混穿（含混紀元及空槽）、合法資產／授權、Registry/SHA、模型／GPU 釋放、manifest/SW/智慧下載、source/publish 隔離與幾何回退。
5. GM 測試中心永久保留正式／自由 fixture 隔離、授權同源 iframe；既有八類 31 案例在重整前必須維持可用。服務／劇情等裝飾場景可以後續候選停用但不得因刪一個完整性哨兵造成全部 loader 失效。
6. JS/CSS 修改需更新適當 HTML cache-bust 並驗 manifest、發布閉包。不得靠刪資料、強制清空快取或跳過啟動／授權讓測試通過。
7. 每批回報固定四項：「修改內容」、「程式自我檢查（已執行／未執行分開）」、「玩家實機驗收清單」、「提交與待補」。報告列明前後 HEAD、Actions exact-HEAD、是否仍需要回退。

## 3. T1：共用資料與控制器解耦（Codex 施工，逐子批）
### T1-A — 正式唯讀資料契約
- 查明 `formal-home.js`、`gm3dprototype.js`、`appearance-snapshot.js` 的 owner；抽離重複的正式地圖／災厄／副本／角色／戰鬥快照解析，讓正式與 GM 使用可查驗的共用契約。
- 銀河最後區域判斷的 F／GM 差異（盤點：101 vs 501）必須從真正正式地圖 owner 判定，不能簡單統一常數；異宇宙「最高完成／目前活動」焦點保留明確語意；高維轉生覆寫的 runtime owner 不得繞過。
- 無真實資料時明確回 unavailable；保持正式快照與 GM 自由 fixture 隔離、iframe 同源／授權、舊 API 相容。先以不改外觀和操作為驗收目標。
- Gate：正式及 GM 主題／紀元／回顧／副本／角色快照測試，八類 31 GM 案例、真實可執行環境測試；不可假裝已完成原來缺少的結果 schema。
### T1-B — 載入、DOM 控制與完整性哨兵拆分
- 把 F 的資產 loader、manifest 指紋、GM 預熱、Observer、預覽按鈕／路由／host 與場景呼叫分層；保留原外部入口與動態延遲載入。
- 解除 F 以 `createServiceConsoleScene`、G 以 Battle／Chronicle 工廠存在與否作「整個模組已完成」的硬依賴，換成恰當能力檢查；正式與 GM 都保留原場景直到 T4。
- Gate：首頁／三紀元地圖／回顧／副本／戰鬥／劇情／服務的開關重開、GM、登入切換、context loss、手機最大化與返回，版本與啟動效能無退步。
### T1-C — 戰鬥事件唯讀橋接最小契約
- 盤點 `combatfx.js` 的 `animateStructuredCombatPresentation(... onUpdate)`、鏡像 adapter、其他模式 owner；定義事件身分、時間／順序、HP／盾、攻擊／命中／閃避／反擊／特殊遭遇／死亡／結算、取消與過期處理。
- 尚無真正式事件者不可憑空生成，先採 adapter＋明確 unavailable；建立事件消費者隔離，不讓動畫 await/sleep 影響正式計算、連戰、音訊 owner。
- Gate：舊正式遊戲原行為不變；事件排序、缺失／重複／取消、前後台、倍速、Fast Catch-up、結果唯一性與授權隔離測試；此階段不建新 2.5D 美術場景。

## 4. T2：2D／2.5D 同場比較原型（隔離，不直接替換正式遊戲）
### T2-A — 比較規格鎖定
- 使用同一套可追溯到正式 owner 的唯讀事件錄製／fixture，同一角色、G007 五槽、同一普通／菁英／Boss 代表、同一背景與顯示資訊。
- 比較純 2D（含可行的角色分層／動畫方案）、即時玩家＋預渲染敵人的 2.5D，以及即時玩家＋即時敵人 2.5D；固定 3/4 視角。對照不得使用不同數值或事件讓某方案看起來較好。
- 測試項目：攻擊與受擊辨識、閃避／反擊／連擊、Boss 進退／壓迫感、換裝清晰度、畫面質感、首次／再次載入、下載大小、解碼記憶體、GPU、60／30 FPS 與長連戰。指標目標由實機基線和同場比較訂定，不編造已達成數字。
### T2-B — 原型實作
- Codex 可建立與正式狀態隔離的開發預覽入口／fixture；不改正式 UI、存檔或音訊流程；開發用素材與正式發布分離。
- 玩家取現有 53 骨模型與 G007 五槽技術；普通／菁英／Boss 各一套代表性立體美術，明示臨時與正式身分關係；禁止臆造正式裝備或怪物名稱。
- 最小戰鬥要能看見位移、出招、命中、受擊、閃避、反擊、結算示意；沒有事件不得自編實際正式數值。
### T2-C — 選型 Gate
- 桌機與實際手機都檢查畫面清晰、發熱、GPU／記憶體、網路冷熱載入、弱網、切頁／回退、持續運行、無過時動作和音效；提供同場錄影／截圖及量測。
- 決策可為混合 2.5D、純 2D 戰鬥＋3D 展示或更保守組合。若未達最低可玩及裝置穩定標準，先修原型，不進正式 T3。
- **只有使用者正式批准技術選型後，才可將草案轉為正式施工規格並啟動大批最終 GLB／怪物資產量產。**

## 5. T3：混合模式與完整正式戰鬥
### T3-A — 模式與品質
- 2D 共用 UI 維持原權限與操作；釐清原 `text/3d` 帳號裝置偏好，新增版本化相容映射，不能直接刪舊偏好。
- 高品質／標準／極簡遵守同一正式戰鬥狀態與事件來源；極簡須具備安全降級與 WebGL 失敗回退。
### T3-B — 正式跨玩法接入
- 正式戰鬥事件 adapter 依模式實裝：銀河／宇宙／高維主線、銀河與宇宙合法懸賞、所有合法競技場（含高維定相／異相三戰）、鏡像、虛空、文明災厄、異宇宙 200×5、特殊遭遇、轉生後回顧與結算。
- 每場正式結果、掉落、解鎖和存檔仍只有原 owner；視覺 renderer 不修改 state。HUD、盾／HP、Boss 身分、標題與正式怪物名稱遵守權威資料。
### T3-C — 自動戰鬥與長連戰
- 驗證 GM 背景、1×／1.5×／GM2×、Fast Catch-up、失焦切回、重播過時事件丟棄、連戰與音效唯一 owner；動畫必須可省略，結果不依賴播放完畢。
- 真實可取得裝置的 30 分鐘以上長測與反覆進出、WebGL context loss、記憶體與 GPU 回收，明確列出沒測到的裝置。
