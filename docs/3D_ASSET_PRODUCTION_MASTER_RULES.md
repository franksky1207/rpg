# 《文明戰線》3D 資產跨批次量產總規範
基準：2026-10-11。適用裝備、普通怪、精英、Boss、場景及後續動作與特效。此文件為**流程補充**，不取代正式遊戲程式碼、已定案的第 27～40 批施工總規格及專項技術契約。修改前一律讀最新 main。

## 1. 資料權威及優先順序
1. 正式身份、掉落、五槽名稱、怪物／Boss、區域與關聯：**main 實際執行中的正式來源程式**。
2. 模型掛點、骨架、遮臉、載入／發布與回退：第 27～40 批正式總規格及對應已實作契約。
3. 本文件規定跨批次製作流程；裝備專項由 [210 套資料庫維護](3D_EQUIPMENT_210_SET_DATABASE_MAINTENANCE.md)、[裝備藝術方向](3D_EQUIPMENT_ART_DIRECTION.md)、[製圖 SOP](3D_EQUIPMENT_CONCEPT_BATCH_ART_WORKFLOW_2026-10-11.md) 詳述。
4. AI 圖片、英文 slug、報告或舊對話不是正式名稱來源。任一衝突應停止相關套裝並列出具體差異，不能強行湊數。

## 2. 單一真實進度與作業狀態
- 每套裝備身份及概念狀態以 `development/3d-source/equipment/concepts/_concept-index.json` 的**腳本產生結果**為準；原始 owner / 圖片檔案 / 使用者批准證據是輸入，索引是衍生輸出，不能手改狀態。
- 不再另建需人工同步的平行進度表；第 2 批若增加批次儀表板，只能由上述索引推導。沒有圖／單圖／雙圖待審／明確批准／已建模但待對齊等狀態不得混淆。
- G001～G010 在 2026-10-11 有兩圖待審；以**執行當下 main** 查證，不把這個歷史數字當永遠有效的狀態。
- 圖片入庫不等於批准；批准不等於模型驗收；CI 綠燈不等於美術通過。
- 使用者明確批准指定圖片版本後才能建立批准證據並推進正式建模；不得由工具假造批准。

## 3. 跨批次執行、續跑與中止
- 裝備預設同大區／連續 Boss **每批十套**，不得默默跨批；重製既有圖需有明確原因。已存在的圖片、notes 人工段落和核准證據要先比對 SHA，預設不覆寫。
- 每批開工前核對最新 main 的 ID、正式名稱、圖片 SHA、待審狀態和前一批提交；只處理尚缺的項目，禁止以「補齊」為名重新生成已存在者。
- 每批完成：兩張概念圖入庫→來源名稱/格式/SHA/尺寸檢查→腳本 generate+validate→unittest→Docs/發布隔離→再次 generate 零差異→獨立 commit→核對 Actions，並回報可用 GitHub 圖片連結。
- 工具中斷或圖片服務不可用：保留已成功的資料，列出已完成／未完成 ID、commit、未過測試及重啟入口；不得宣稱全批完成，或用假的圖片佔位。
- 美術顯著退化、正式映射不一致、批次三套以上需重大重畫或發布隔離失敗時，停止進下一批，先調查。
- 各批日後須支持可重入、可驗證、已核准不可覆寫；自動化與負向測試列為下一工程批工作，不在本文件批次修改。

## 4. 畫圖、用圖、建模、交付
- 依**正式中文名稱**與設計 notes 先產概念，不得反過來用圖片創造物品身份。先做全身正／側／背，再參照產五槽拆解；跨圖輪廓／分件不一致時需修正並標明。
- 精緻高品質要求包括：主輪廓、結構層次、表面材質、少量關鍵色光、裝配邊界、縮小可辨識度；禁止僅換色的批量套版。
- 不具影像生成能力的 Codex **不可假稱已製圖**。可交由有圖片生成能力的環境產圖，再由工具自動壓縮、入庫、索引；使用者不應手動搬運幾百張圖。
- AI 概念圖不是工程精準三視圖；批准後建模仍須用 rig、尺寸、掛點、LOD、遮蔽及手機渲染逐項校正。完整骨架／裝備分槽不得為了還原圖片而破壞。
- 資產類型不得硬套共用模板：玩家裝備需五槽拆解；怪／精英重輪廓、招式與比例；Boss 重多階段及辨識；場景重實際鏡頭與空間、光照、效能；動畫／VFX 重時間節奏與降級。後續對應正式來源核對後再建立專項索引。

## 5. 容量與發布隔離
- 原始高解析概念圖可以外部封存；GitHub 開發資料保留可供建模的兩張標準 WebP，原則每張 ≤800 KB，若更小仍清楚可用。遇細節模糊不可為了壓縮硬犧牲。
- 已提交的二進位檔舊版本仍會留在 Git 歷史中；不鼓勵反覆覆寫大型圖或堆積候選素材。高容量 .blend／烘焙中間檔按雙軌發布規格控管，Git LFS 也有配額。
- 開發概念圖、未核准工作檔**不得列入** Pages、Service Worker 及首屏下載清單。正式發布只含優化後必要資源；壓縮比、下載量、repo 大小應分別回報，不得互相混淆。

## 6. 固定回報（每批）
1. 修改：ID、正式名稱來源、圖檔位置、既有保護、差異化重點。
2. 自檢：生成/驗證/CI、SHA、零差異、發布資產隔離與失敗項；不得臆稱實機通過。
3. 使用者可驗收：全部圖片入口、美術待審點、手機注意項目。
4. 提交與待補：SHA、Actions 真實狀態、下一批與暫停原因。
