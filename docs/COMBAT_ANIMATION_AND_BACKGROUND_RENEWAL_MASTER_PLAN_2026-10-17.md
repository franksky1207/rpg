# 《文明戰線》戰鬥動畫與背景系統優化・新版總規劃（討論草案）

日期：2026-10-17。狀態：**只建立新版規劃；尚未授權或執行新版第1批**。正式遊戲與施工進度一律以 GitHub `main` 的實際程式碼及同 SHA Actions 為唯一真實來源。本計畫不復活舊第28～40批或舊清理第6批編號；**新版批次從第1批重新起算**，避免混淆。

## 一、已確認的產品方向

1. 遊戲本質為文字／數值養成 RPG，正式戰鬥核心、存檔與結算只有一套。角色動作、浮字、音效、場景屬**戰鬥動畫／呈現層**，不以「3D模式」或「2.5D模式」對外稱呼。
2. 建議玩家設定使用「戰鬥動畫」開關；一般戰鬥畫面不應常駐「切換文字戰鬥」、「戰鬥視覺暫不可用，已保留文字戰鬥」等工程式提示。必要錯誤保留可追查的診斷與文字安全回退。具體 UI 行為待討論核准。
3. GM 對外名稱建議「GM 動畫測試中心」，整理正式入口、測試描述與現役能力；內部 `3d-test/` 及 API 不得為改名盲目批次替換。
4. 三紀元未來各一套完整角色外觀：銀河、宇宙、高維。高維裝備轉生後可繼續顯示高維外觀；正式 210 套裝備 ID／1,050 槽與玩法數值不變。不沿用已清理的 G001～G095 概念圖或舊逐套量產 SOP。
5. iPhone 異宇宙戰鬥「**進入動畫播放才顯著卡頓及發熱**，桌機與其他模式未見同樣程度」，屬使用者實測症狀。尚無手機 CPU/GPU trace，原因未定論；不可把疑點報成已確診。

## 二、不可變更的正式遊戲契約

- 三紀元主線、懸賞、競技場、鏡像、虛空、災厄、回顧、連戰及異宇宙等合法模式：攻擊次數、傷害、HP／盾、特殊特性、獎勵、每日次數、戰鬥 owner、時間節奏、結果不因動畫／背景優化更改。
- 背景戰鬥、極簡、離線收益、Fast Catch-up、GM 倍速與樣本依各自**正式 owner**運作；不可把背景連戰誤當離線樣本獎勵，不能重複結算／重複寫入。
- 保留 Save Schema 17、Future schema fail closed、轉生／突破／異宇宙狀態、登入／雲端安全、Service Worker、音訊持久化；無授權不得修改玩家持久化格式。
- 文字顯示與動畫資源缺失、WebGL 失效、頁面背景化均須保持正式戰鬥結果和安全回退；極簡維持完全靜音。保留必要 GM 診斷、資源 SHA 與正式發布隔離。
- 不建大型全介面 3D，不復活 210 套角色／武器、420 張概念圖或舊批次量產；不提前製作三套新角色美術。

## 三、新版批次草案（可在每批施工前修訂）

### 新版第1批：全戰鬥架構與背景系統唯讀稽核
- 盤點每種戰鬥：計算／結算 owner、事件契約、動畫入口、HP／盾、音效、背景、極簡、倍速、生命週期、存檔／獎勵與現有測試。
- 特別比對**異宇宙為後加入的模式**：已調用 `runWorldCombatCore()` 與 `animateStructuredCombatPresentation()`，但進入、回退、結束／結算與其他模式可能不同；以差異清單和測試證據判定是否需要整合，不能先假設獨立引擎。
- 背景鏈盤點：`backgroundprogress.js`、`battlepipeline.js`、`combatpacing.js`、`gmbackground.js`；離線鏈盤點：`offlineprogress.js`、`offlinestatecore.js`、`offlinefarmtarget.js`；核對 `visibilitychange`、`blur/focus`、`pagehide/pageshow`、時鐘、補算、檢查點及 UI 節流。
- 建立普通戰鬥與異宇宙的事件數、長任務、同步版面重算、浮字同時數、動畫後清理、手機／桌機的可重現效能基線；缺少真機量測要明列未驗證。
- **此批原則上只稽核及定稿後續施工清單；不重構正式 Runtime。**

### 新版第2批：全戰鬥契約與背景／離線執行優化
- 按第1批有證據的重複與不一致處整合呈現、背景、回前景、快轉、GM 倍速與資源釋放；異宇宙專屬結算和特性仍由自身 owner 負責。
- 檢查背景 UI 更新、checkpoint 頻率、Fast Catch-up 節流、重入與重複恢復；避免不必要運算，但**不變動收益公式、節奏、上限或實際結果**。
- 補跨模式背景與離線安全回歸，驗證跨紀元、極簡、頁面切換與雙重結算防護。

### 新版第3批：iPhone 與全模式戰鬥動畫效能
- 優先處理異宇宙動畫播放時的 lag／發熱，量測 `combatfx.js` 強制讀取 `offsetWidth`、密集 DOM 動畫／浮字、HP／盾 MutationObserver、事件節流及資源清理。
- 不砍正式戰鬥事件、不改攻擊或獎勵；允許僅在**顯示層**合併非關鍵重複效果、避免重排、控制同時裝飾浮字，必要資訊及同步時鐘不變。
- 建立比較測試與手機壓力驗收；沒有 iPhone 真機 trace 不宣稱已解決發熱。

### 新版第4批：介面與命名統一
- 釐清「文字戰鬥為正式核心＋可選戰鬥動畫」的設定行為，對外採「戰鬥動畫」，移除誤導性 3D／2.5D 宣傳與多餘戰鬥內切換按鈕。
- 正常文字、極簡、背景狀態不顯示工程式回退警告；實際載入失敗維持安全回退與 GM 診斷。
- GM 對外統一「GM 動畫測試中心」，整理仍有效的角色動作／戰場測試；修正 iPhone HP、浮字、狀態字、操作區的重疊與安全區。

### 新版第5批：三紀元動畫、角色與場景完善（待另行核准美術）
- 先訂銀河／宇宙／高維三套外觀的唯讀呈現契約、轉生後外觀規則、資源與 GM 驗收；是否開始製圖、動作、突刺、敵人／背景製作需使用者明確另行決定。
- 技術與美術難度以小尺寸戰鬥動畫為基準，不重回大型 3D 或 210 套逐件角色模型。

### 新版第6批：跨模式整合驗收與封箱
- 回歸三紀元及所有合法戰鬥、音樂音效、背景／離線／Fast Catch-up、極簡、倍速、轉生、存檔／雲端隔離、手機與桌機。
- 檢查資源載入、快取、正式發布、GM、GitHub Actions 和 Pages；記錄真機／雲端未測範圍，完成整體封箱。批數與順序仍可據第1批稽核調整。

## 四、強制施工 SOP：每批一次整合施工、檢查、Actions、封箱

**預設一次授權只執行一個已確認範圍的完整批次，不再預設拆成需要使用者逐次喊「繼續」的 1-1／1-2 小批次。**

1. **開始前**：fresh-read 最新 `main` SHA、handoff、本總規劃及受影響 runtime、tests、workflows；列出完整依賴、必要共同修改、可觀察驗收項、基線和停止條件。不要只追一條錯誤訊息修補。
2. **集中施工**：在同次工作內完成本批互相依賴的正式程式、GM、測試、文件及發布契約修改；優先減少碎片提交；不碰批次外玩法與正式持久化契約。
3. **修改後自我檢查**：語法、檔案引用、差異、靜態檢查、代表性測試、正式資料／存檔／獎勵安全斷言；絕不為全綠關閉必要測試或掩蓋失敗。每次寫 GitHub 後重新 fetch 實際檔案與 commit diff，不能只看回傳成功。
4. **Actions 逐 SHA 驗收**：提交後核對該**實際最新 SHA** 的必要工作流程，失敗時一次整合檢視 jobs／logs／根因及受影響範圍，再集中修正；不拿舊 SHA 全綠證明新 SHA。需要等待外部 CI 時如實留下進度，不宣稱已通過。
5. **封箱報告**：在 `docs/` 記錄四段——「修改內容」「程式自我檢查」「實機／Actions 驗收」「提交 SHA 與待補事項」；明列通過工作流程的 URL、驗證 SHA、保護契約、未測事項。**報告提交也產生新 SHA，須區分報告提交 SHA 與已驗收 SHA；若要求最終 HEAD 全綠則須另驗收新 SHA。**
6. **溝通方式**：同一次可執行範圍內連續處理，不為可自行解決的細節反覆要求確認；外部工具、授權、安全阻擋、重大玩法變更或必需的真機測試才暫停並具體告知。不能保證跨訊息無限執行，也不能假稱背景持續工作。
7. **封箱後**：已全綠批次不因無必要的程式修改反覆重測；新增需求進下一批或修訂計畫，保留已有保護測試。

## 五、討論與核准門檻

- 本規劃僅是**可修改的討論草案**，非第1～6批一次全部施工許可；每批仍需使用者明確指示開始。
- 首先討論新版第1批的稽核清單、模式覆蓋範圍、性能量測方法及是否需要在第1批產出正式文件；未討論確定前不修改 Runtime。
- 此規劃取代「舊清理第6批＝下一批」的口語安排，但不改寫過去第5批清理封箱證據和舊專案歷史。
